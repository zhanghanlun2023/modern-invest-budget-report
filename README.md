# 现代投资股份有限公司 · 合并报表系统（框架原型 v0.1）

比照**久其报表系统**设计，左侧组织单位树，右侧**横排三张主表**，支持**自下而上逐级汇总**与**合并抵销**。
纯静态、零依赖、零联网，**双击 `index.html` 即可运行**（不需要 Node/Python/数据库）。

> **当前已在本机运行： <http://127.0.0.1:8777/>** —— 直接点开即可。
>
> **同一网段同事可访问： <http://172.18.4.100:8777/>**（`172.18.4.0/24`）
> 已绑定 `0.0.0.0` 并放通防火墙入站规则 `现代投资合并报表原型-8777`（仅 `LocalSubnet`）。
> 撤销共享：`Stop-Process` 结束 python 进程 + `Remove-NetFirewallRule -DisplayName '现代投资合并报表原型-8777'`。
> 注意：无登录鉴权，能访问到该地址的人即可看到原型内容。

### 若出现 `ERR_EMPTY_RESPONSE (-324)`

原因是**系统代理拦截了内网地址**。Windows 的 `ProxyOverride = <local>` 只对不含点的主机名生效，
**匹配不到 `172.18.4.100` 这类 IP 字面量**，于是浏览器把内网请求交给了代理（如佛跳墙 / Clash / 公司 VPN），
代理连不上私网地址就返回空响应。服务端本身是正常的。

排查与修复：

```powershell
# 1. 直连是否正常（正常=200 说明是代理的问题，不是服务的问题）
curl.exe --noproxy "*" -s -o NUL -w "%{http_code}" http://172.18.4.100:8777/index.html

# 2. 把私网地址段加入代理绕过列表（HKCU，用户级，不影响 VPN 本身）
$key = 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings'
$e = @('<local>','localhost','127.*','10.*','192.168.*')
$e += (16..31 | ForEach-Object { "172.$_.*" })
Set-ItemProperty -Path $key -Name ProxyOverride -Value ($e -join ';') -Type String
```

改完**关闭全部浏览器窗口再重开**（Chrome/Edge 每进程缓存代理配置）。
回滚：把 `ProxyOverride` 改回 `<local>`（原值备份在 `tools\_proxy_override_backup.txt`）。
同事若也装了代理工具，需要在他们机器上做同样处理，或临时关闭系统代理。

## 三、操作流程（验收路径）

### A. 在某一个节点上做自下而上的汇总合并

1. **看默认态** — 打开即选中 `现代投资股份有限公司` 根节点，口径为**合并态**，
   三张主表直接呈现 `汇总数 | 抵销数 | 合并数` 三列。
2. **点左侧任意一个节点** → 表区立刻变成**该节点范围内的汇总/合并**。
   节点栏（表区顶部）会用面包屑显示 `现代投资股份有限公司 › 高速公路板块 › 怀芷高速`，
   并列出 `范围 N 户 / 口径 / 抵销笔数`。
   - 点 `高速公路板块` → 只看这 5 户的板块汇总合并；
   - 点 `公司总部` → 总部单户；点 `合计` → 全集团 23 个填报主体。
3. 节点栏上也有 **「在此节点汇总」/「在此节点合并」** 两个按钮，等价于工具条 ②③。
4. **勾选/取消左侧复选框** → 汇总范围实时变化，节点栏、状态栏、三张表同步重算。
5. **点「③ 合并抵销」** → 被抵销的行标红加亮，**点该行**可下钻看到是哪几笔分录、借贷各多少。
6. **点「审核校验」** → 7 项检查 + 内部往来对账差异明细 + 抵销分录构成。

只有**全部腿都落在当前合并范围内**的分录才参与本次合并 —— 所以选单个板块时，
集团层面的权益抵销自动不参与，这才是正确的合并范围语义。

### B. 单元格录入（单户填报）

1. 点左侧某个**单位节点**（如「怀芷高速」）→ 切到**单户填报态**，
   表头变成 `期末余额 | 年初余额`，可录入的格子鼠标移上去会**高亮描边**。
2. **单击任意可录入单元格** → 出现输入框，直接改数。
   - `Enter` 确认并**下移**一格；`Tab` 确认并跳下一格；`Esc` 取消；点别处也会确认。
3. 小计 / 合计行（如 `流动资产合计`、`资产总计`、`净利润`）是**公式行**，
   鼠标是禁止样式，不可录入，数值随录入自动重算。
4. 录入后：本户表内公式重算 → 逐级汇总重算 → 合并抵销重算，三张表和状态栏**同步刷新**；
   树上有录入的单位会出现橙色 **「改」** 标记。
5. **「自动配平」**（默认开）：改动资产/负债行后，差额自动轧差到 `未分配利润`，
   保持 `资产总计 = 负债和所有者权益总计`。关掉它就能看到校验栏报 `✖ 本户资产负债表不平`。
6. `未分配利润`、`少数股东权益` 两行不参与自动配平（前者是配平项本身，后者由合并产生）。
7. **「重置数据」** 丢弃本次全部手工录入，回到初始模拟数据。

### C. 调整界面宽窄

- **组织树 ⟷ 表区**：拖动中间那条竖向分隔条；**双击它复位**到 302px。
- **三张主表之间**：拖动表与表之间的竖向分隔条，可任意加宽某一栏
  （改过宽度后随窗口缩放按比例自适应）。
- **底部抽屉**：拖动抽屉顶部横条调整高度。

### D. 其它

`抵销分录` 抽屉可看全部分录、**新增手工分录**（一借一贷，保存后立即参与合并重算）、重新自动生成；
`布局` 可在**横排三栏**与**页签切换**之间切换；`导出 Excel` 导出当前口径三张表。

## 七、合并抵销

### 7.1 分录结构

```
voucher = { id, type, memo, legs: [ { side:'D'|'C', unit, table, line, amt } ] }
```

只有**全部腿都落在当前合并范围内**的分录才参与本次合并 —— 选单个板块时，
集团层面的权益抵销自动不参与，这正是正确的合并范围语义。

### 7.2 四类自动分录

| 类型 | 分录 | 抵销对象 |
|---|---|---|
| 权益抵销 | 借 子公司实收资本/资本公积/其他综合收益/盈余公积/未分配利润（全额）<br>贷 总部长期股权投资（`E×持股比例`）、贷 子公司少数股东权益（`E×少数股权比例`） | 长投与所有者权益 |
| 少数股东损益 | 借 归母净利润 / 贷 少数股东损益（亏损时借贷对调） | 净利润拆分 |
| 内部往来 | 借 应付方其他应付款 / 贷 应收方其他应收款 | 内部资金拆借；**双方不一致时按较小方抵销**，差额进对账差异表 |
| 内部购销 + 内部现金流 | 借 卖方营业收入 / 贷 买方营业成本<br>借 买方购买商品支付的现金 / 贷 卖方销售商品收到的现金 | 内部交易与内部收付 |

### 7.3 合并算法（保证抵销后仍然平衡）

```
合并数(行) = 汇总数(行) + dir(行) × (抵销借方 − 抵销贷方)
    dir = +1  借方科目（资产、成本费用、现金流入）
    dir = −1  贷方科目（负债、所有者权益、收入、现金流出）
小计 / 合计行 = 用已抵销的下级行按公式重算（不是简单相加）
抵销数(行) = 合并数(行) − 汇总数(行)
```

**平衡性是可证的**，不是凑出来的：每笔分录借贷恒等，
且所有抵销都成对作用于「资产 ↔ 负债+权益」，因此合并后
`资产总计 = 负债和所有者权益总计` 依然成立。启动自检会验证这一点。

## 九、本原型刻意的简化（请在评审时确认）

1. **数据是模拟的**（确定性伪随机，每次打开数值一致）。但每户资产负债表严格自平衡、
   现金流量表期末现金 ≡ 货币资金、集团合计约 660 亿元，量级贴近真实。
   **手工录入只存在内存里，刷新页面即还原**（点「重置数据」也可还原）。
2. **年初/上期数**：合并口径下只重算本期。按会计准则，合并报表「年初余额」应
   **结转上期合并结果**而非本期重算，这一结转逻辑留待下一轮设计。
3. **内部往来与内部购销是两套独立台账**，尚未做「往来—交易—现金流」三方联动校验。
4. **长期股权投资处置、分步取得、商誉减值、内部股权投资收益与利润分配的抵销**
   目前不生成分录（表样中也没有利润分配表），这是合并抵销最需要补的一块。
5. 板块是管理口径虚拟分组。若组织树要严格按法人层级（含三级、四级子公司），
   需要把 `data.org.js` 换成真实股权结构树，表结构与引擎不用改。
6. 金融类单位（岳阳巴陵农商行、小贷、担保）**吸收存款等科目不在通用表样内**，
   按你的「通用一套表」要求暂未单列。
7. **录入没有做「只能填明细行、合计由公式算」之外的业务校验**（如合理性、上下限、
   跨表勾稽阻断）。目前靠「审核校验」事后发现，例如把 `货币资金` 改大而不同步现金流量表，
   校验会提示 `现金勾稽` 不一致。

## 十、目录结构

```
modern-invest-report/
├─ index.html            页面骨架（顶部条 / 工具条 / 树 / 三栏 / 抽屉 / 状态栏）
├─ 启动.cmd              本地起 HTTP 服务（有 Python 时）
├─ 引擎自检.cmd          跑 tools/smoke.js，校验汇总与合并勾稽
├─ README.md             本文档
├─ assets/
│   └─ app.css           久其风格样式：密集网格、蓝灰配色、冻结表头列
├─ tools/
│   └─ smoke.js          引擎冒烟测试（Node 环境，不依赖浏览器）
└─ src/
    ├─ data.org.js       组织单位树（31 节点 = 合计 + 3 板块小计 + 7 汇总分组 + 20 单位 + 总部 + 2 调整项）
    ├─ data.tables.js    三大主表表样（行次、层级、公式）
    ├─ engine.js         汇总 / 合并抵销 / 审核校验 计算引擎（纯函数）
    ├─ seed.js           模拟数据生成 + 四类抵销分录自动生成
    └─ app.js            界面渲染与交互
```

> 引擎（`engine.js`）与数据（`seed.js`）与界面（`app.js`）完全解耦：
> 后续接真实数据库/接口时，只需替换 `MI.dataset` 的形状，界面与合并算法不用改。
